# Implementation Plan — Task 6.5: Frontend Unit Tests

Set up Vitest (already bootstrapped in 6.1) and write component tests for all UI components and WebSocket state handling.

---

## Test Stack

Per `AGENTS.md`:
> Testing: Vitest (not Jest) — `package.json`'s `"test"` script must point to `vitest run`. Vitest was chosen specifically because it shares Vite's config/transforms, so `.vue` SFCs need no extra transform setup. Every component under `src/components/` gets a matching spec under `tests/components/`.

Dependencies needed (added in 6.1 via `create-vue --vitest`):
```
@vue/test-utils
jsdom               ← Vitest environment
vitest
```

`vite.config.js` must include:
```js
test: {
  environment: 'jsdom',
  globals: true,
}
```

---

## Test Files

### `tests/components/VoiceVisualizer.spec.js`
- **Setup**: Mock `navigator.mediaDevices.getUserMedia` and `AudioContext` globally in `beforeEach`.
- **Tests**:
  - When `active = false` (default): `getUserMedia` is NOT called.
  - When `active` prop changes to `true`: `getUserMedia` is called once.
  - When `active` reverts to `false`: stream tracks are stopped (mock `.stop()` called).
  - Emits `error` event if `getUserMedia` rejects.
  - Canvas element is present in the DOM.

---

### `tests/components/ChatArea.spec.js`
- **Setup**: Mock `api.createSpeechWebSocket` to return a mock WebSocket object with `send`, `close`, and an `onmessage` setter.
- **Tests**:
  - Mounts without error; WebSocket is created on mount.
  - Simulating an incoming `token` message updates `partialResponse` in the chat store.
  - Simulating a `done` message commits the partial response to `messages`.
  - Simulating a `transcript` message adds a user message to `messages`.
  - PTT button click calls `audioStore.startListening()`.
  - Cancel button is hidden when `isSpeaking = false`; visible when `isSpeaking = true`.
  - Cancel button click sends `{type: "cancel"}` on the WebSocket.

---

### `tests/components/DocumentManager.spec.js`
- **Setup**: Mock `api.uploadDocument` to resolve with `{ document_id: 1, chunk_count: 5 }`.
- **Tests**:
  - Drop zone renders correctly.
  - File input `change` event triggers `documentStore.upload()`.
  - `uploading = true` shows a spinner; `uploading = false` hides it.
  - After successful upload, a document card appears with the correct chunk count.
  - API error sets `documentStore.error`.

---

### `tests/components/SessionSummaries.spec.js`
- **Setup**: Mock `api.createSummary` to resolve with a structured summary object.
- **Tests**:
  - "Generate Summary" button calls `summaryStore.generate()`.
  - `generating = true` shows a spinner.
  - After generation, a summary card appears with topics, vocabulary table, and mistakes.
  - Multiple generates produce stacked cards.

---

## Running Tests

```bash
cd frontend
npm test        # → vitest run (exits 0 for CI)
npm run test:watch   # → vitest (watch mode for development)
```

`package.json` scripts:
```json
"scripts": {
  "test": "vitest run",
  "test:watch": "vitest"
}
```
